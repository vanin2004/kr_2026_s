# Архитектура приложения (Low-Code / Configuration-driven / Microservices)

Данная архитектура спроектирована с упором на минимизацию программирования (Low-Code) и максимальное использование готовых решений через конфигурацию. Подход базируется на паттерне **"Область данных через Backend-as-a-Service"** и микросервисах для сложной бизнес-логики.

## Основной стек технологий

1. **API Gateway / Reverse Proxy**: Nginx
2. **База данных**: PostgreSQL
3. **Low-Code REST API (Связка с БД)**: PostgREST
4. **Identity & Access Management (IAM)**: Keycloak
5. **Микросервис сложной логики**: FastAPI (Python)

---

## Как работает связка (Nginx + Postgres + PostgREST + Keycloak)

То, о чем вы слышали — это утилита **PostgREST**. Она подключается непосредственно к вашей базе данных PostgreSQL и "на лету" генерирует полноценный, безопасный и быстрый RESTful API. 

Вместо того чтобы писать сотни строк кода на Python для базовых CRUD-операций (Create, Read, Update, Delete), вы настраиваете базу данных:
* **Keycloak** берет на себя регистрацию, логин и выдачу JWT токенов.
* **Nginx** перенаправляет запросы к `/api/` непосредственно в PostgREST, а к `/auth/` — в Keycloak.
* **PostgREST** принимает запрос пользователя с JWT-токеном, проверяет подпись токена (настроенную на интеграцию с Keycloak).
* **PostgreSQL RLS (Row-Level Security)**: Вся авторизация (кто какую строку может читать/изменять) решается на уровне базы данных. В JWT токене от Keycloak передаются роли и ID пользователя, PostgreSQL читает эти данные через локальные переменные транзакции и применяет политики RLS.

**Результат**: 80-90% функционала API (весь CRUD) работает **вообще без написания backend-кода**, только за счет миграций SQL.

## Архитектурная схема (Компоненты)

### 1. Reverse Proxy (Nginx)
Единая точка входа для клиентских приложений (Android / Web).
- `/auth/*` -> проксируется на **Keycloak**.
- `/api/data/*` -> проксируется на **PostgREST**.
- `/api/custom/*` -> проксируется на **FastAPI**.

### 2. IAM Service (Keycloak)
Готовый enterprise-ready сервис авторизации.
- Хранит учетные данные пользователей.
- Предоставляет готовые экраны логина/регистрации (по желанию) или API для них.
- Выпускает JWT токены. Ролям Keycloak сопоставляются роли PostgreSQL.

### 3. Data Service (PostgREST)
Не требует программирования, только конфигурационных файлов.
- Предоставляет доступ к представлениям (Views) и таблицам PostgreSQL.
- Понимает пагинацию, фильтрацию `?age=gte.18`, сортировки из коробки.

### 4. Database (PostgreSQL)
Центр управления бизнес-правилами для данных.
- Хранит все данные.
- **Row Level Security (RLS)**: написанные на SQL правила (например: `CREATE POLICY user_see_own ON users FOR SELECT USING (id = current_user_id());`).
- **Database Functions**: простые вычисляемые поля или триггеры можно написать на PL/pgSQL.

### 5. Custom Logic Microservices (FastAPI + Python)
Используется **только** для тех задач, которые невозможно или нецелесообразно решать средствами SQL или PostgREST.
- Работа со сторонними API (например, отправка SMS, email, интеграция с платежными системами).
- Сложные алгоритмы (например, алгоритм подсказок — `suggestion_alg.md`).
- Сервис является отдельным микросервисом. Он сам авторизует запросы (либо тоже читает JWT из Keycloak, либо находится за Nginx, который валидирует токен). 
- Для работы с данными FastAPI-сервис может обращаться напрямую к PostgreSQL (через asyncpg/SQLAlchemy) с правами сервисного аккаунта.

## Жизненный цикл типичного запроса

**1. Получение данных (Например, загрузка профиля и списка постов):**
1. Приложение запрашивает `/api/data/posts` с HTTP-заголовком `Authorization: Bearer <JWT>`.
2. Nginx отправляет запрос в PostgREST.
3. PostgREST проверяет валидность JWT, переключает роль БД на нужную (например, `web_user`) и устанавливает `request.jwt.claims` в контексте транзакции.
4. Выполняется `SELECT * FROM posts`. Срабатывает RLS, и БД "на лету" фильтрует записи так, что возвращаются только те посты, которые разрешены данному пользователю.
5. Ответ в формате JSON летит клиенту. *Код не написан, работает с производительностью уровня С/Rust.*

**2. Сложная логика (Например, запуск алгоритма подбора рекомендаций):**
1. Приложение запрашивает `/api/custom/suggestions`.
2. Nginx маршрутизирует запрос в микросервис FastAPI.
3. FastAPI (используя библиотеку вроде `python-keycloak` или встроенный jwt-декодер) удостоверяется, что пользователь авторизован.
4. FastAPI выполняет сложную логику, обращается к БД, формирует рекомендации и отвечает клиенту.

## Выгоды такого подхода

- **Zero-Boilerplate для CRUD:** Не нужно писать сериализаторы, Pydantic-модели и роутеры FastAPI для каждой таблицы в базе данных. Вы просто создаете таблицу.
- **Безопасность Data-Centric:** Правила безопасности находятся прямо в БД. Даже если к БД подключится стороннее приложение, RLS не позволит совершить утечку.
- **Масштабируемость:** Граница между "простым чтением/записью" и "сложными вычислениями" четко проведена. PostgREST крайне производителен и требует мало RAM, а Python масштабируется только под конкретные вычислительные узлы.
- **Конфигурируемость:** Keycloak закрывает 100% болей с OAuth2, 2FA, сбросом паролей без единой строчки Python-кода.
