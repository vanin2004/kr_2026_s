# План разработки Backend-части платформы

Данный план содержит декомпозированные задачи для backend-разработчиков, DevOps-инженеров и Database-архитекторов для запуска микросервисной архитектуры (Nginx + Keycloak + PostgreSQL + PostgREST + FastAPI).

## Эпик 1: Инфраструктура и Базовые сервисы
Задачи по развертыванию базового окружения и маршрутизации.

* **[TASK-1.1] Настройка Docker Compose среды для локальной разработки**
  * **Описание:** Подготовить `docker-compose.yml`, включающий PostgreSQL, Keycloak, PostgREST, Nginx и скелет FastAPI.
  * **Критерии приемки:** Все контейнеры поднимаются, сервисы видят друг друга во внутренней сети.
* **[TASK-1.2] Настройка Keycloak (Auth Service)**
  * **Описание:** Создать Realm для приложения. Настроить OAuth2/OpenID Connect клиент (client_id). Завести базовые роли (Realm Roles): `tutor`, `student`. Получить публичный ключ / секрет для валидации JWT токенов.
  * **Критерии приемки:** Можно получить токен по логину/паролю. В токене содержится роль пользователя и его `user_id`.
* **[TASK-1.3] Конфигурация Nginx (API Gateway)**
  * **Описание:** Реализовать маршрутизацию (Reverse proxy). `/auth/` направлять в Keycloak, `/api/data/` в PostgREST, `/api/custom/` в FastAPI.
  * **Критерии приемки:** Запросы корректно проксируются, вырезаются/пробрасываются нужные заголовки (CORS, Authorization).

## Эпик 2: Database Layer и Zero-Code API (PostgreSQL + PostgREST)
Задачи по проектированию данных и Data API без написания кода.

* **[TASK-2.1] Написание миграций схемы БД (DDL)**
  * **Описание:** Создать скрипты инициализации таблиц согласно ER-модели: `users`, `tutor_profiles`, `student_profiles`, `tags`, `tutor_tags`, `schedules`, `lessons`, `applications`, `chats`, `messages`, `test_library`, `student_results`, `reviews`.
  * **Критерии приемки:** Таблицы корректно создаются, связи (Foreign Keys) и индексы заданы.
* **[TASK-2.2] Настройка PostgREST и JWT-аутентификации в БД**
  * **Описание:** Передать в PostgREST секрет Keycloak для валидации токенов. Создать роли БД, соответствующие ролям Keycloak (`authenticator`, `web_tutor`, `web_student`, `anon`).
  * **Критерии приемки:** PostgREST принимает токен Keycloak и задает локальные переменные транзакции (например, `current_user_id`).
* **[TASK-2.3] Настройка Row-Level Security (RLS) политик**
  * **Описание:** Написать SQL RLS-политики. *Примеры:* Ученик может редактировать только свой профиль (`id = current_user_id()`); Репетитор видит свои чаты; Расписание репетитора доступно на чтение всем, а на запись - только самому репетитору.
  * **Критерии приемки:** Невозможно прочитать или изменить чужие конфиденциальные данные через `/api/data/`.
* **[TASK-2.4] Разработка триггеров БД (Автоматизация)**
  * **Описание:** Написать PL/pgSQL функции. 1) При создании пользователя в Keycloak (или первой авторизации) — автоматически создавать запись в `users` и пустой профиль. 2) При переходе `applications.status` в `accepted` — создавать чат.
  * **Критерии приемки:** Триггеры отрабатывают без ошибок и поддерживают целостность процессов.

## Эпик 3: Custom Business Logic API (FastAPI)
Задачи по разработке микросервиса для сложной логики.

* **[TASK-3.1] Инициализация проекта FastAPI**
  * **Описание:** Настроить проект (Poetry/Pip, структура папок). Настроить подключение к PostgreSQL (SQLAlchemy / asyncpg). Написать middleware для валидации JWT от Keycloak.
  * **Критерии приемки:** Сервис отвечает на `GET /api/custom/health`. Запросы без валидного токена отклоняются (401).
* **[TASK-3.2] Разработка алгоритма ранжирования репетиторов (Recommendation Engine)**
  * **Описание:** Реализовать эндпоинт `POST /api/custom/suggestions`. 
    1. Жесткая фильтрация SQL (пересечение расписания, цена, предмет). 
    2. Умное ранжирование (Soft Scoring): расчет коэффициента совпадений (теги, эффективность, коммуникабельность) на основе переданных весов.
  * **Критерии приемки:** Эндпоинт возвращает отсортированный по `score` список преподавателей. Алгоритм не падает при отсутствии тегов.
* **[TASK-3.3] Разработка джоба пересчета рейтингов (Bayesian Ratings)**
  * **Описание:** Реализовать эндпоинт-воркер (или cron-джоб) `POST /api/custom/jobs/recalculate-ratings`. Высчитывает метрику эффективности ($O_1$) по разнице контрольного и стартового тестов. Высчитывает коммуникативность ($O_2$) по отзывам. Обновляет `tutor_profiles`.
  * **Критерии приемки:** Регулярный пересчет корректно агрегирует новые оценки и обновляет показатели профилей без race conditions.

## Эпик 4: Тестирование и документация
* **[TASK-4.1] Покрытие логики FastAPI тестами (Pytest)**
  * **Описание:** Написать Unit-тесты для алгоритма Suggestion и расчета байесовских рейтингов для покрытия крайних случаев (пустые данные, максимумы).
* **[TASK-4.2] Интеграционное тестирование API**
  * **Описание:** Подготовить Postman-коллекцию для сквозных сценариев (Логин Keycloak -> Запрос в PostgREST -> Подбор в FastAPI).
